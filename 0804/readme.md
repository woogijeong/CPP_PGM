
객체지향의 마법: 상속(Inheritance)으로 코드에 날개 달기

1. 상속의 첫인상: "물려받는다는 것"의 의미

우리가 일상에서 사용하는 '상속'이라는 단어는 보통 부모님의 소중한 무언가를 물려받을 때 사용하곤 하지요. 프로그래밍 세계에서의 상속도 이와 아주 닮아 있답니다. 예를 들어, "철수가 아버지로부터 매력적인 목소리와 훤칠한 키를 물려받았다"라고 할까요? 이때 철수는 아버지가 이미 가진 신체적 특징을 처음부터 다시 만들 필요 없이, 그대로 이어받아 자신의 것으로 누리게 됩니다.

이처럼 프로그래밍에서의 **상속(Inheritance)**이란, 한 클래스가 다른 클래스에서 정의된 속성(데이터와 함수)을 그대로 이어받아 사용하는 것을 말합니다. 마치 잘 지어진 튼튼한 집을 물려받아 그 위에 예쁜 다락방 하나만 더 얹는 것처럼, 이미 검증된 클래스를 바탕으로 필요한 기능만 살짝 추가하여 새로운 클래스를 만드는 지혜로운 방법이지요.

핵심 요약: 상속을 이용하면 부모님께 재산을 물려받아 기반을 다지는 것처럼, 이미 완성된 소프트웨어를 재사용하여 훨씬 쉽고 빠르게 자신만의 프로그램을 개발할 수 있습니다.

"그렇다면 우리가 부르는 이 '부모'와 '자식'에게는 프로그래밍 세계에서 어떤 이름표가 붙어 있을까요?"

2. 상속의 이름표: 핵심 용어 한눈에 보기

상속 관계에 있는 두 클래스는 우리가 바라보는 관점에 따라 조금씩 다른 이름으로 불립니다. 아래 표를 통해 정리해 보아요.

용어 종류 (부모 쪽)	용어 종류 (자식 쪽)	특징 설명
베이스 클래스 (Base Class)	파생 클래스 (Derived Class)	구현의 관점에서 '기초'가 되는 클래스와 이를 바탕으로 '파생'된 클래스를 뜻합니다.
부모 클래스 (Parent Class)	자식 클래스 (Child Class)	관계의 관점에서 물려주고 물려받는 가족 같은 유대감을 직관적으로 표현합니다.
슈퍼 클래스 (Superclass)	서브 클래스 (Subclass)	계층적 관점에서 '상위' 범주와 그에 속한 '하위' 개념(부분집합)임을 강조합니다.

💡 인사이트: 왜 이렇게 이름표가 많을까요? 그것은 개발의 맥락에 따라 강조하고 싶은 부분이 다르기 때문입니다. 관계를 중시할 때는 '부모/자식', 실제 구현 방식을 따질 때는 '베이스/파생', 그리고 전체적인 구조의 높낮이를 볼 때는 '슈퍼/서브'라는 용어를 선택하여 소통하는 것이지요.

"이름표를 확인했으니, 이제 이들이 실제로 어떻게 연결되는지 그 설계도를 살펴봅시다."

3. 상속의 설계도: 코드와 비유로 이해하는 문법

C++에서 상속을 구현하는 방법은 아주 간단합니다. 'Car'라는 기본 자동차 클래스가 있고, 이를 상속받아 'SportsCar'를 만드는 코드를 함께 살펴볼까요?

class Car { // 베이스 클래스 (자동차)
public:
    int speed;    // 속도
    int gear;     // 기어
    string color; // 색상 (부모가 가진 기본 속성)

    void speedUp(int increment) { speed += increment; }
};

// SportsCar가 Car를 public으로 상속받음
class SportsCar : public Car { 
public:
    bool turbo; // SportsCar에만 새롭게 장착된 확장 기능
    void setTurbo(bool newValue) { turbo = newValue; }
};


위의 설계도를 보면 SportsCar는 자기 자신 안에 speed나 color를 직접 선언하지 않았지요? 하지만 Car로부터 물려받았기에 이 모든 것을 마치 자기 것처럼 자유롭게 사용할 수 있답니다. 특히 주목할 점은 **'확장'**입니다. 단순히 물려받는 데 그치지 않고, 기존의 일반적인 주행 기능에 '터보 모드(turbo)'라는 강력한 추진력을 새롭게 장착함으로써 더 멋진 존재로 거듭난 것이지요.

"설계도를 보니 아주 효율적이죠? 그런데 왜 우리는 굳이 상속이라는 번거로운 과정을 거쳐 코드를 짜는 걸까요?"

4. 왜 상속인가? 상속이 주는 3가지 선물

상속은 단순한 편리함을 넘어 프로그래머에게 소중한 3가지 선물을 안겨줍니다.

* 코드 재사용을 통한 생산성 향상: 똑같은 코드를 반복해서 쓸 필요가 없습니다. 중복을 줄이면 프로그램의 덩치가 가벼워지고 제작 속도는 훨씬 빨라집니다.
* 신뢰성 있는 소프트웨어 유지보수: 이미 잘 작동하는 베이스 클래스를 그대로 사용하므로 버그가 줄어듭니다. 수정이 필요할 때도 베이스 클래스만 고치면 모든 자식들에게 적용되니 관리가 참 편하겠지요?
* 계층적 관리의 용이성: 복잡한 GUI 프로그램이나 거대한 시스템도 상속을 통해 구조화하면, 어떤 객체가 어디에 속해 있는지 한눈에 파악할 수 있는 튼튼한 뼈대가 생깁니다.

"장점을 알았으니, 이제 객체가 태어나고 사라지는 신비로운 순서를 알아볼 차례입니다."

5. 객체의 생로병사: 생성과 소멸의 골든 타이밍

상속 관계에 있는 객체가 생성되고 소멸될 때는 부모와 자식 간의 예의를 지키듯 엄격한 순서가 있답니다.

1. 생성 순서: 베이스 클래스 → 파생 클래스
  * 부모님이 계셔야 자식이 태어날 수 있는 이치와 같습니다. 메모리가 할당되면 부모의 생성자가 먼저 축하의 인사를 건네며 실행되고, 그 뒤를 이어 자식의 생성자가 실행됩니다.
2. 소멸 순서: 파생 클래스 → 베이스 클래스
  * 사라질 때는 생성의 역순입니다. 자식이 먼저 작별 인사를 하고 사라지면, 마지막으로 부모의 소멸자가 실행되며 메모리를 정리합니다.

⚠️ 주의사항: 생성자 호출의 의무 파생 클래스는 부모의 멤버까지 초기화해야 할 책임이 있습니다. 따라서 아래 예시처럼 **이니셜라이저(Initializer)**를 사용해 부모의 생성자를 명시적으로 불러주어야 합니다.

"잠깐! 부모의 모든 것을 자식이 다 가질 수 있는 건 아닙니다. 거기엔 특별한 규칙이 있거든요."

6. 접근 제어: "이건 너만 써, 이건 같이 쓰자"

부모가 가진 소중한 보물들도 그 성격에 따라 자식에게 공개하는 정도가 다릅니다. [SOURCE_IMAGE_21]의 비유를 통해 쉽게 이해해 볼까요?

* private: 안방 깊숙이 숨겨둔 **'금궤 상자'**와 같습니다. 자식에게조차 보여주고 싶지 않은 비밀이라, 자식 클래스에서도 접근할 수 없습니다.
* protected: 우리가 함께 사는 '집' 그 자체입니다. 외부인은 함부로 들어올 수 없지만, 우리 가족(자식 클래스)만큼은 자유롭게 드나들 수 있도록 허용하는 따뜻한 배려이지요.
* public: 정원에 세워진 **'비너스 조각상'**과 같습니다. 지나가는 사람도, 가족도 누구나 자유롭게 감상하고 접근할 수 있는 열린 공간입니다.

상속 형태에 따른 접근 권한 변화:

상속 방식	부모의 멤버 권한	파생 클래스에서의 권한
public 상속	public / protected	그대로 public / protected 유지
protected 상속	public	protected로 수준을 높여 제한함
private 상속	public / protected	모두 private으로 꽁꽁 숨김
공통 사항	private 멤버	어떤 상속 방식이든 접근 불가 ❌

"마지막으로, 상속을 올바르게 사용하기 위해 꼭 기억해야 할 황금률이 있습니다."

7. 상속의 황금률: "is-a" 관계를 확인하세요

상속은 강력한 도구이지만, 아무 때나 사용해서는 안 됩니다. 가장 중요한 기준은 바로 **"파생 클래스는 베이스 클래스의 일종인가?(is-a 관계)"**라는 질문에 "예!"라고 답할 수 있어야 한다는 것이지요.

* 스포츠카는 자동차이다 (SportsCar is a Car): 아주 자연스럽지요? 상속을 사용하기에 완벽한 관계입니다.
* 대학생은 사람이다 (UnivStudent is a Person): 이 역시 논리적입니다. 훌륭한 설계이지요.

만약 "경찰은 몽둥이다"처럼 논리가 어색하다면 그것은 상속을 쓸 때가 아닙니다. 무분별한 상속보다는 이처럼 논리적인 계층 구조를 갖추는 것이 좋은 소프트웨어 설계를 결정짓는 핵심 열쇠가 된답니다.

객체지향 프로그래밍의 가장 아름다운 마법인 '상속'의 기초를 성공적으로 마스터하신 것을 진심으로 축하드려요! 이제 여러분은 앞서간 거인들의 어깨(이미 만들어진 클래스) 위에 올라타 더 넓은 세상의 코드를 설계할 준비가 되었답니다. 이 소중한 원리를 발판 삼아, 여러분만의 멋진 코드 세계를 마음껏 탐험해 보시길 응원하겠습니다!
